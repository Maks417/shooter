## Working conventions (read before each step)

- **One ADR per step.** ADR-087 owns both Wave 1b tranches; ADR-088 through ADR-094 implement the later waves. The next unused number is **ADR-095**. Append to `docs/decisions.md` with Context, Decision, Consequences, Evidence and Rollback, as in ADR-084 to ADR-086. Add a VD-D row to `visual-defect-inventory.md` and update the brandbook when tokens change. Afterwards run `python docs/verify_docs.py --refresh-manifest`, then `python docs/verify_docs.py`.
- **Pure first.** Put math, timing and recipes in Unity-free folders linked by `Tools/*` projects: `Presentation/Model/**` goes to `Tools/Presentation.Model` and is tested in `Tools/Simulation.Tests`; `Generation/Core/**` goes to `Tools/Generation` and is tested in `Tools/Generation.Tests`. Keep them C# 9 / netstandard2.1. Determinism needs IEEE add/sub/mul/div/sqrt only: no `Math.Sin`/`Cos` in anything that is hashed.
- **Cross-lane goldens.** Any generated bytes get a SHA-256 golden in a .NET test plus an EditMode twin with the same constant. See `IconAtlasTests` and `IconAtlasEditModeTests`, or `AmbientOcclusionVolumeTests`.
- **Unity files.** Every new file or folder under `UnityProject/Assets` needs a `.meta` with a fresh GUID. Copy an existing meta and replace the guid.
- **Editor changes.** Any change under `Bootstrap/Editor` (for example adding a preloaded shader in `ShooterBuild`) needs a run of `ShooterBuild.WriteSettingsProvenance`:

  ```powershell
  & (Get-Content .local/unity.json | ConvertFrom-Json).editorPath -batchmode -projectPath UnityProject -quit -executeMethod ShooterBuild.WriteSettingsProvenance -logFile $env:TEMP/prov.log
  ```

  New shaders must be added to the client preload list in `ShooterBuild` (see `UiSdf.shader`).
- **No image files in the player.** The build's art audit fails on packed `.png`/`.tga`/etc. Generated textures are built in memory (like `UiIconAtlas`) or shipped as package artifacts through the SGAF codec (like the ADR-081 AO volume).
- **Content changes.** These include map or weapon recipes, new package artifacts and `Content/*.json`. Run `./Tools/Compile-GameContent.ps1` (and `-Native`); when the change is to a frozen generator, also do a reviewed `feature-content-lock.json` refreeze. Weapon visual fields come from `Content/Weapons/*.weapon.json` via `python Tools/generate_weapon_catalog.py` (`--check` in CI).
- **Checks per step:**
  - `./Tools/Test-Simulation.ps1`, `Test-Generation.ps1`, `Test-Game.ps1`, `Test-Maps.ps1` (when maps change) and `Test-SourceProvenance.ps1`;
  - `./Tools/Test-Unity.ps1 -Mode EditMode`;
  - `./Tools/Build.ps1 -Target Client`, then `./Tools/Smoke.ps1 -BuildRunDirectory <build-run>`;
  - for render-cost-sensitive steps, a diagnostic `./Tools/Benchmark.ps1 -BuildRunDirectory <build-run> -Workload TDM-5v5-v1 -Profile Low -RunIndex 1`. Recent Low frame p95 baseline: 4.7–5.5 ms. This is diagnostic, not a reference capture.
- **Player review.** Use `./Tools/Capture-UiReview.ps1`; its header documents the key syntax, entering a match, held Tab and the `-shooterUiGallery 1|results` previews. Store captures under `Artifacts/visual-design/<adr>/<date>/`. The tool takes over the desktop while it runs.
- **Commits.** Commit each finished step to `main` with the evidence recorded in its ADR. Server builds are deferred (local-only scope).

### Pitfalls already hit

- IMGUI draws in linear colour space: pass brand colours through `UiSdf.Out` (`Color.linear`), and pass text through `TacticalUi.StyleInk`.
- Custom IMGUI materials must multiply by `_GUIClipTexture` / `unity_GUIClipTextureMatrix`, or scroll views and groups won't clip.
- EditMode code paths must use `DestroyImmediate` when `!Application.isPlaying`, because the EditMode tests bind presentation objects.
- The menu stage renders at 30 Hz, so `ProductMenuScene.sceneTime` under-counts real time about 3×. Use `Time.unscaledTime` for anything that needs real pacing. The dust motes still use `sceneTime`.
- `PrintWindow` returns stale D3D frames, so capture with the window in front. `SendKeys` can't hold keys; use `HOLD:vk,scan`.
- Don't leave a shell's working directory inside `Artifacts/<…>`, or the wrappers' run pruning fails on a locked folder.

## Step 3 — Wave 2: world materials and lighting (ADR-088 to ADR-091)

Order matters: materials, then surface shader, then decals, then sky and grading.

1. **`material.noise` generator (ADR-088).** This is a new generator id; `material.surface` 1.0.1 and 1.1.0 stay frozen.
   - Build it in `Generation/Core/Materials` on `Generation/Core/Noise/NoiseField` (FastNoiseLite double port, ADR-075). Use the seeded `NamedRandomStream`, and tile with the `NoiseField` periodic wrapper.
   - Roles:
     - concrete with cellular cracks and water staining;
     - plaster with patchy repaint;
     - rust/oxide with domain-warped downward streaks;
     - painted steel with chipping;
     - asphalt with aggregate and tar seams;
     - gravel/dirt, corrugated-metal grime and camo fabric (also used by step 5).
   - Output albedo/normal/mask triplets at the existing 2 m tile and 128 px resolution, or 256 px on High only.
   - Add a schema in `docs/feature-schemas`, fixtures, `feature-content-lock.json` and `verify_feature_registry.py` rows. Goldens go in both lanes.
   - Maps opt in through their map definitions (`Content/Maps/*.map.json`, ADR-083) by naming material roles, then a content republish.
2. **MapSurface shader (ADR-089).** In `Shaders/MapSurface.shader`, keep the URP Lit forward pass and add:
   - grime driven by the AO volume (darker, rougher albedo where `_AoVolume` is low);
   - a height-band dirt splash near y = 0;
   - triplanar detail normals to break up tiling;
   - a macro-variation noise multiply at about 20 m scale.

   Keep one keyword variant (`ShooterPostProcessingBuild` creates the variant material). Measure Low cost.
3. **Decals (ADR-090).** Generate a decal atlas in code: stencil letters and numbers, hazard stripes, unit markings, oil stains, scorch marks and bullet holes. Ship it as a package artifact through SGAF, not an image file.
   - Balanced/High use a code-configured URP Decal renderer feature added in `ShooterPostProcessingBuild` (provenance plus settings regeneration).
   - Low uses mesh quads.
   - Static decal placement comes from layout documents (a new `decal` kit operation, `ArenaLayoutDocument` version bump; `content-format-lock` refreeze if the schema changes).
   - Bullet holes are runtime decals from `ShotAccepted` impacts (a pooled ring of 64, presentation only).
4. **Sky, atmosphere and grading (ADR-091).**
   - Analytic sky shader with a cloud layer baked once from `NoiseField` into a cubemap at load, plus per-map time of day through the registry `sky` hint: Compound morning haze, Depot overcast, Oil Depot golden hour.
   - Height fog, and a reflection probe re-rendered from the new sky (`GeneratedReflectionProbe`).
   - Per-map 32³ colour LUT generated from numeric grade parameters in the map definition and applied through the ADR-080 global volume (`ProductPostProcessing`). Low stays LDR with colour adjustments only.
   - Actor lighting: sample the AO volume at the actor root for soldiers and weapons (one value per actor, as a material property), plus a blob contact shadow on Low.
   - Acceptance for all of Wave 2: map captures in sun and shade, a doorway-to-yard transition and a combat view at 720p Low. The Low benchmark must still be within budget.
