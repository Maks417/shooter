Route sample interpolation is linear at fixed tick between waypoints, yaw shortest-arc, pitch0 unless specified. B02 camera is a noncolliding diagnostic rig, so route is not affected by generated obstacles. ## Fixture freeze and result schema

At M3 finalize camera/input trajectory and generated target/corridor validation, store resulting manifests and route hashes. If B02/B03 impossible under first planner, change recipe/workload version with evidence before accepting baseline. Benchmark correctness counters: actor count, emitted accepted shots, active impacts, smoke proxies, chunk transitions, visible triangles and scene object counts. At60 Hz, player fires at tick0 and every6 ticks; during measured interval[3600,14400) expect1800 shots excluding warmup events. Missing shots invalidates workload rather than improving performance score.

Result required fields: schemaVersion,workloadId,seed,sourceCommit,toolchainHash,contentManifestHash,routeHash,profile,internalWidth,internalHeight,warmupSeconds,captureSeconds,runIndex,machine{cpu,gpuAdapter,ramBytes,ramSpeed,channelMode,os,driver,powerPlan,acPower},metrics{frameMs{p50,p95,p99,max},mainMs,renderMs,gpuMs,privateCommitBytesPeak,rssBytesPeak,managedBytesPerFrame,managedBytesPerTick,uploadMsP95},counters{actors,shotsAccepted,impactPeak,smokeProxies,chunkTransitions},unavailableMetrics[],gateStatus. All timings ms, memory bytes; unavailable values null with reason, never0. Percentiles nearest-rank indexceil(p×n)−1 of sorted raw values; track every capture frame. GateStatus ComputedPass/ComputedFail/PendingHardware; reviewer signoff separate. Schema and tiny deliberately unmeasured example are in fixtures.

Collector version 3 uses the [ADR-016 conservative render-budget method](decisions.md#adr-016--accepted-conservative-render-budget-proof-and-continuous-thermal-conditioning): result renderMs is the complete CPU-frame-start-to-Present p95 upper bound on active render work. The 8 ms limit is unchanged and applied to this larger value. Its mandatory wrapper proof identifies the method, endpoints, clocks, containment controls and native work unavailability; raw native render values remain unchanged. Earlier collectors report native active-work p95 where complete. These methods are explicitly distinguished when comparing results. A separately recorded preconditioning phase may precede the fixed 60-second warmup; captureSeconds remains 180 and measured tick count 10800, with actual start tick recorded.

## No benchmark shortcut

Fixed workload performance passes do not prove full gameplay correctness. Run normal eight-bot soak with ordinary firing and objective/restart tests. All three timing runs must pass; 60 FPS stretch uses identical B03 ID/content/counters. Do not compare B01-minimal with B01-materials or benchmark-invulnerable scene with playable combat without naming the difference.

The implemented M1-content-gallery-v1 renderer/cache smoke remains a separate diagnostic with weapons and seven material cubes and is rejected as a benchmark substitution. B01-materials-v1 now has its own `MaterialBenchmarkView`, fixed-tick `MaterialBenchmarkRecipe`, verified material leases, canonical material manifest/route hashes and recorder/analyzer/wrapper integration. Per-tick view indices and per-rendered-frame camera checks validate the route. CPU texture inventory and scene triangles are explicitly distinct from GPU allocation, visible triangles, draw calls and measured variant counts. Three full release runs and thermal/resource acceptance remain separate gates; gallery diagnostics cannot satisfy them.
